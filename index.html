The Problem

Engineering Bottlenecks We Face

  • ❌ Large PRs that are difficult to review (>700 lines, >15 files)
  • ❌ Manual PR comment triage from multiple sources
  • ❌ Sprint tickets with incomplete or missing context
  • ❌ Inconsistent commit messages and release notes
  • ❌ Ticket scoping requires extensive back-and-forth

Result: Slower velocity, context switching, review fatigue

The Solution

Intelligent AI Agents

Six specialized agents that automate repetitive engineering tasks:

  1. pr-stacker - Split large PRs into reviewable stacks
  2. pr-comment-reviewer - Systematically triage PR comments
  3. analyze-queue - Identify and fill in incomplete sprint tickets
  4. ticket-scoper - Collaborative ticket breakdown
  5. commit-message-writer - Generate conventional commits
  6. doctor-mobile-release-notes - Automated release documentation

PR Stacker - Overview

Problem:

Large branches exceed review thresholds (>700 lines added, >15 files changed)

Solution:

Intelligent PR stack creation that maintains:

  • ✅ Logical coherence (components + styles + types together)
  • ✅ Git history preservation
  • ✅ Buildable incremental changes
  • ✅ Clear dependencies between PRs

Command: /stack-pr or use pr-stacker agent

PR Stacker - Workflow

Phase 1: Analysis

  • Calculate accurate metrics (excluding generated/test files)
  • Identify merge commits and scope correctly
  • Analyze commit history for natural groupings

Phase 2: Strategy Design

  • Group files by functional relationships
  • Order changes to create buildable stack
  • Ensure each PR ≤700 lines, ≤15 files

Phase 3: Plan Presentation

  • Show proposed split with metrics
  • Get user approval before making changes

Phase 4: Execution

  • Create branches with preserved git history
  • Optionally push and create draft PRs via gh CLI

PR Comment Reviewer - Overview

Problem:

PRs receive comments from multiple sources (teammates, Copilot, bots)
Manual triage is time-consuming and inconsistent

Solution:

Objective, context-aware analysis of PR comments with actionable recommendations

Key Features:

  • Fetches unresolved comments from any source (teammates, Copilot, bots)
  • Presents numbered list with action menu for each comment
  • Actions: analyze | address | resolve | resolve-with-comment | skip
  • Analyzes comments in code context (validity, likelihood, impact, effort)
  • Provides objective recommendations
  • Batch commits multiple fixes

Command: /review-pr-comments or use pr-comment-reviewer agent

PR Comment Reviewer - Analysis Framework

Evaluation Criteria:

  1. Validity - Is the concern technically correct?
  2. Likelihood - How likely is this scenario to occur?
  3. Impact - What's the consequence if ignored?
  4. Effort - How much work to address?
  5. Applicability - Does it fit the platform (React Native vs web)?
  6. Feasibility - Can this be addressed in current scope?

Output Format:

Analysis: Comment 3 - Null pointer handling
Context: Function processes user input from form
Current behavior: Assumes field is always populated
Comment's concern: Field could be null in edge cases
Likelihood: Medium | Impact: High | Effort: Trivial
Recommendation: ADDRESS
Adding a null check prevents potential crash with minimal effort.

PR Comment Reviewer - Workflow

Interactive Triage Process:

  1. Fetch - Get all unresolved PR comments
  2. Present - Show numbered list with action menu
  3. Analyze - Evaluate comment when requested
  4. Execute - Apply fixes or resolve with explanation
  5. Commit - Batch multiple fixes into single commit

GitHub Integration:

  • Uses gh CLI for PR operations
  • GraphQL API for thread resolution
  • Replies to comment threads with reasoning
  • Tracks progress: "Comment 3 of 7"

Analyze Queue - Overview

Problem:

Sprint tickets often have incomplete or template content
Engineers spend time manually identifying and filling in missing context

Solution:

AI-powered ticket preparation that identifies incomplete tickets and helps add necessary context

Capabilities:

  • Identifies tickets with empty or minimal descriptions
  • Detects default template content that needs filling
  • Helps add descriptions, requirements, and resources
  • Analyzes codebase for relevant context
  • Updates tickets directly in Linear

Command: /analyze-queue

Analyze Queue - Use Cases

When to Use:

✅ Sprint Start

  • Prepare tickets for development
  • Fill in template content
  • Ensure tickets are actionable

✅ Before Standup

  • Review incomplete tickets
  • Add missing context
  • Prepare for daily sync

✅ PM Handoff

  • Add technical details
  • Define acceptance criteria
  • Link related resources

Ticket Scoper - Overview

Problem:

Large tickets need breakdown into subtasks
Estimations require context from code, designs, and related tickets

Solution:

Collaborative ticket breakdown with full context loading

Workflow:

  1. Load Context
    • Fetch Linear ticket details
    • Pull related project information
    • Load Figma designs if referenced
    • Read relevant codebase files
  2. Propose Breakdown
    • Create logical subtask grouping
    • Provide effort estimates
    • Identify dependencies
  3. Create Subtasks
    • Generate detailed ticket descriptions
    • Link to parent ticket
    • Set appropriate priorities

Command: /scope-ticket (plus ticket ID)

Commit Message Writer - Overview

Problem:

Inconsistent commit messages make changelogs unclear
Manual message writing is repetitive

Solution:

Automated conventional commit message generation

How It Works:

  1. Analyzes git diff (staged or unstaged)
  2. Determines appropriate action prefix
  3. Identifies scope and impact
  4. Generates concise, actionable message
  5. Follows imperative mood and team conventions

Action Prefixes:

  • add - New features or functionality
  • fix - Bug fixes and corrections
  • update - Modifications to existing features
  • refactor - Code restructuring
  • docs - Documentation changes
  • test - Test additions
  • chore - Maintenance tasks

Command: /commit

Commit Message Writer - Examples

Example 1: New Feature

Diff: Added authentication middleware + login route
Message: add: user authentication with JWT tokens

Example 2: Bug Fix

Diff: Fixed null pointer in payment processing
Message: fix: null pointer exception in payment validation

Example 3: Refactor

Diff: Restructured API client classes
Message: refactor: API client to use dependency injection

Example 4: Multiple Concerns

Recommendation: Split into 2 commits
Commit 1: add: video playback component
Commit 2: fix: video thumbnail loading issue

Quality Checks:

  • Action verb is accurate
  • Message is concise but complete
  • Uses imperative mood
  • Will make sense in changelog

Doctor Mobile Release Notes - Overview

Problem:

Creating release notes from commits is manual and time-consuming
Technical jargon doesn't translate well for stakeholders

Solution:

Transform git commits into stakeholder-friendly release documentation

Features:

  • Analyzes commits affecting apps/doctor-mobile/
  • Filters out version bumps, merges, and noise
  • Categorizes changes by type
  • Translates technical details to user benefits
  • Uses Slack markdown for easy sharing
  • Updates RELEASE_NOTES.md automatically

Command: /doctor-mobile-release

Doctor Mobile Release Notes - Workflow

Phase 1: Commit Analysis

  • Identify commits since last release
  • Filter to Doctor Mobile directory only
  • Exclude version bumps, merges, and duplicates
  • Handle new release branch scenario

Phase 2: Categorization

✨ New Features      - feat:, add: commits
🔧 Bug Fixes        - fix: commits
🎨 UI/UX Improvements - improve:, style: commits
🔒 Security         - Security-related changes
📱 Platform Updates  - iOS/Android specific changes
🛠️ Technical Improvements - refactor:, performance
📚 Documentation    - User-facing docs

Phase 3: Generation

  • Transform technical commits to user-friendly language
  • Group related changes under descriptive headers
  • Include PR numbers for reference
  • Present draft for approval

Technical Architecture

Built on Claude Code Framework

Agent Architecture:

  • Each agent is a specialized .md file in .claude/agents/
  • Agents have specific models (Sonnet), colors, and descriptions
  • Commands in .claude/commands/ invoke agents via Task tool

Integration Points:

  • GitHub: gh CLI for PRs, comments, and operations
  • Linear: MCP server for ticket management
  • Figma: MCP server for design integration
  • Git: Direct git commands for history analysis

Key Tools Used:

  • Bash (git, gh CLI)
  • Read/Edit/Write (file operations)
  • Grep/Glob (code search)
  • Task (agent orchestration)

Best Practices

When to Use Each Agent:

Agent Use When Don't Use When
PR Stacker Branch >700 lines or >15 files Branch already reviewable
PR Comment Reviewer Multiple unresolved comments No comments to review
Analyze Queue Sprint start, incomplete tickets Tickets already well-documented
Ticket Scoper Large/complex ticket needs breakdown Ticket already well-scoped
Commit Message Writer Any commit Trivial single-line changes
Release Notes Preparing release deployment Mid-development commits

Pro Tips:

  • Run PR Stacker proactively before creating large PRs
  • Use PR Comment Reviewer on Copilot while your PR is in draft - thoroughly review and resolve bot comments before putting up for review
  • For Analyze Queue: create all your tickets with titles (empty) from sprint themes before running
  • Scope tickets early to improve estimation accuracy

Key Takeaways

What We Learned:

  1. Specialization Works - Each agent has a clear, focused purpose
  2. Context is King - Agents that read code/designs/tickets make better decisions
  3. Human in the Loop - Agents present plans, humans approve
  4. Integration Matters - GitHub, Linear, and Figma integration is crucial
  5. Incremental Adoption - Start with simple agents, expand based on value

Success Factors:

  • Clear agent descriptions with examples
  • Consistent command interface
  • Prompt to get what you want from the bot - ask for updates to the agent for incremental improvements
